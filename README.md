# The LIT Crowd - Print Forge

Спільний репозиторій команди для працювання над практичною роботою 3D Modeling App.
Учасники: Славін Святослав, Козачко Артем.

У цьому репозиторії ми разом з командою розробляємо проєкт, суть якого - підбити підсумки всього вивченого за наданий термін.

Тут розробляємо, створюємо, пишемо, лагодимо код.

## Як працюємо

Для кожного завдання чи зміни:

1. Онови локальну гілку `features` і створи окрему гілку.
2. Внеси зміни та перевір, що вони працюють.
3. Зроби коміт із коротким і зрозумілим описом.
4. Відкрий pull request: поясни, що змінив і як це перевірити.
5. Дочекайся review, обговори зауваження та внеси виправлення.
6. Після погодження об’єднай зміни з `features` через merge.

**Окрема гілка → коміт → pull request → review → merge.**

## Правила

- Не додавай коміти безпосередньо до `main`.
- Не додавай до репозиторію паролі, токени, секретні ключі та локальні дані.
- Роби невеликі зміни, які легко прочитати й перевірити.
- Став запитання, пояснюй свої рішення та допомагай іншим розібратися.

## Branches (гілки)

 - `main`, як основна гілка
 - `develop`, як гілка, на якій розробляємо, відколота від `main`
 - `features`, як гілка, відколота від `develop`, на якій відколюєчи нові гіки, створюємо поетапно проєкт. Як наслідок, окремі "частинки" мерджимо з `features`
 - `bugs`, як гілка, на якій вирішуємо непрацюючі моменти у коді ДО РЕЛІЗУ, відколота від `develop`
 - `hotfix`, як гілка, на якій виправляються помилки коду (пропущена чи переплутана кома, точка) ПІСЛЯ РЕЛІЗУ, відколота від `main`

## Merge requests (запит на мердж)

Після успішного (на вашу думку) виконання "частини" feature проєкту, маємо надати запит для мерджу гілки з гілкою `features`.

Обов'язкові умови для merge:
 - хоча б один approval від тіммейта на гітхаб
 - вирішення питань коду (незрозумілі моменти, ідеї, його скорочення, пояснення) повинні бути обговорення на гітхаб
 - вирішення merge-конфліктів
